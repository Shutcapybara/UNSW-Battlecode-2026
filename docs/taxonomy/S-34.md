# S-34 — C++ port and exception fixes (ares-v02–v05, hunter-v14, ouroboros-s02 boot turn)

**Kind:** Solution · **Status:** accept · **Ledger:** L22, L05 · **Last reviewed:** 2026-09-30

exceptions that the Python catch-all had silently turned into fallback moves.

## Verdict and why it stopped
- Verdict: accept — D-029: "Ares is the production C++ line. It is Tyr V12's strength with the exceptions fixed and
  90 M points of headroom." V04–V06 remained "experimental" against the BENCHMARKS gate.
- Why it stopped: it did not stop; it became the base of every later Ares/R-lane bot. The individual steps stopped as
  follows — V01: "No V02 or follow-up tuning run was made after this V01 screen"; V02/V03 superseded by the parity
  approach (golden harness exposed semantic gaps: partial body state, override block, density coordinates, crown
  order, separation transitions, exception behaviour); V05: "No seed-2 confirmation was run" at writing.
  hunter-v14: "not a tactical improvement yet. Diagnose the `big_empty` losses before considering submission"
  (README); no later diagnosis recorded — not stated why.
- Consequence for other entries: every Python-era verdict that was capped or confounded by the CPU wall or by the
  two silent exceptions (all tyr versions carry them, pa1 notes) was measured on a host the production line no longer
  shares — see [S-33](S-33.md), [S-62](S-62.md), [S-54](S-54.md).
- Revival condition: L22 (0.2) stays dormant — "Ares V06 (more logic) is the best bot".
