# S-37 — Opening rescue split (scholze-v02, gavroche rescue, Ares opening path, renoir-10a)

**Kind:** Solution · **Status:** accept · **Ledger:** — · **Last reviewed:** 2026-09-30

At rounds 0–2 a long starting dragon whose tail lies outside the 7×7 view (so the host cannot prove its split is
legal) splits off rear segments anyway, and incomplete-body production splits early, so long spawns are not
paralysed in corridors.

## Where it lives
- Lineages: gavroche v01–v14 (MC chassis, Python); scholze-v02-rescue-opening (on fafnir); odin v02/v03; inherited by
  gavroche-final → yuna → tyr → Ares (C++) as `opening_rescue_split` / opening production.
- Code / docs: `bots/gavroche-v01…v14-*/README.md`, gavroche-v66 policy.py:L435 `opening_rescue_split`;
  `experiment_data/strategy_leaks_20260927T000855Z_scholze/REPORT.md` §Dossier 1; `docs/odin.md`;
  Ares `bots/ares-v06-expanded-search-support/policy.hpp:1096-1114, 1418-1423` (c1 notes); `docs/findings/2026-09-30-ra-lane.md` (10a).

## What it computes / does
- Problem addressed: the host's split needs the full body (`if len(body) < L: return None`), so an L ≥ 8 spawn in a
  narrow corridor could not split (P-25; scholze Dossier 1: Autarky B vs O13 control 8 units at r100, eliminated r405).
- gavroche v01–v14: rescue variants — L−2, balanced L/2, head-preserving SPLIT 2, 4-segment head, paced/one-shot/
  two-stage, map-aware ≤600 tiles. Params (v66): rescue until r1, min_len 8, initial id limit 6, value 8; opening
  production r1–30, unit cap 32, value 8.
- scholze-v02: rescue L−2 at r ≤ 2 for L ≥ 8 with body not fully seen; early incomplete-body production r ≤ 20,
  L ≥ 4, units < 8.
- odin v02: tail rescue + child-2 production to r30 (all maps); v03 gated ≤625 tiles.
- Ares (production, C++): same path — fires only when `body.size() < len`; renoir-10a/b vary the production window
  (30 → 15 / 60).

## Verdict and why it stopped
- Verdict: accept — the mechanism is in the Ares production line through the Tyr/yuna inheritance; its Python-era
  evidence is 16–36-game screens on 2–6 maps (gavroche v10/v12 "results were schedule-dependent").
- Why it stopped: gavroche moved on to dive caps and gradient push from v15 (pa2 §5); scholze's lineage ends at v05
  with the three "PROMOTED" arms and no later version or cross-line adoption — stop not stated; odin stop not stated.
  On Ares the window knob is inert because the path only fires on incomplete bodies (c1 notes: "consistent with the
  opening path firing only on incomplete bodies") — (inferred) there is nothing left to tune in this form.
- Host flag: Python-era screens; the mechanism itself runs on the production host, where only its window was varied.
- Revival condition: none on the ledger. Related open line: the starved-opening problem on Trauma/Dilemma
  ([S-28](S-28.md)) is a different opening failure (nothing ripe), not paralysis.
