# S-61 — Roles at creation (kraken, hydra, leviathan, ouroboros, estuary)

**Kind:** Solution · **Status:** hold · **Ledger:** L14, L31, L33 (context) · **Last reviewed:** 2026-09-30

Specialise dragons as scouts, hunters and gatherers (plus crown/feeder), decided at birth — by child size, by a parent's
sonar hand-off, or re-decided from local state — the user's original design brief for the four AI lines.

## Where it lives
- Lineages (all Python): kraken-v01..v05 (role = child size: 2 scout, 3 hunter, ≥ 4 gatherer), hydra-v01..v03 (same, v03
  phases scale with map area), ouroboros-v01..v13 (role = weight slice, child role chosen by the parent as "most
  under-represented" vs phase mix, delivered by K_HANDOFF through the tail), leviathan-v01..v07 (state roles), leviathan-
  x03 Estuary (live allocation with shares, hysteresis, scout retirement). Ares (C++) has forager/crown/feeder only, plus
  small-dragon hunting from r200.
- Code / docs: `docs/design-framework.md` §2; `docs/kraken-design-framework.md` §3; `docs/ouroboros-design.md` §3, §6;
  `docs/macro-spec.md` §0; ouroboros `roles.py:L19-80`, `defaults.py:L119-129`; kraken-v05 main.py want_split L1106-1140;
  `docs/leviathan/DESIGN.md`; `bots/leviathan-x03-estuary-roles/README.md`; `docs/leviathan/ESTUARY_BOT_HANDOFF.md`.

## What it computes / does
- kraken/hydra: phase schedule decides child size (scout_until 110 → 2, hunter_until 330 → 3 if len ≥ 5); role-specific
  trade margins (scout needs len ≥ mine + 2).
- ouroboros: GATHER/HUNT/SCOUT/CROWN weight slices (risk mult, trade margin, w_pearl, w_frontier, w_enemy …); phase mixes
  early (0.45, 0.25, 0.30) <r120, mid (0.45, 0.45, 0.10) <r360, late (0.70, 0.30, 0); maps ≤ 600 cells all-gatherer
  early; orphans (no hand-off heard) default to HUNT.
- leviathan-v01..v07: short before r90 = scout, default hunter, long or r ≥ 360 gatherer. Estuary: scout_share 0.22,
  hunter_share 0.25, role_period 16, scout retirement at coverage 0.8 or r340, scouts spend 3/4 rays on discovery packets.

## Verdict and why it stopped
- Verdict: size-coded roles rejected ("Drop: size-encoded roles", family-comparison); weight-slice roles kept in
  ouroboros without a clean ablation ("converged in form", HANDOFF §4.3) — hold; dynamic roles superseded; Estuary rejected.
- Why it stopped: macro-spec §0 fact 4 — "Roles are cheap; role-carrying material is not"; kraken-v05 "null result — not
  promoted", v06 never built; leviathan v08 — "adopting the measured survival/crown reference provides a stronger
  convergence base than maintaining v07's missing components"; Estuary — "This phase did not perform the full 110-game
  gauntlet or broad tuning" and "compute margin remains a concern" (98.8 M); D-006 — "Portal explorers are a hypothesis
  (H-portal), not a role"; the Ares line never had birth roles.
- Host flag: all measured on Python hosts, Estuary at the CPU edge; never built on Ares.
- Revival condition: L14 (0.3) scout splits for one-way places (the panel lacks dead ends: maps/new 0/20 — Sophie);
  L31 (0.5) modes conditioning weights (the dynamic form of a role); L33 (0.4) warding — "S-5's scout split (one scout per
  pocket …) is the hand-built special case".

## Discrepancies
- LINEAGE_REVIEW calls leviathan's roles "decorative"; the ouroboros finding that orphan hunters are "load-bearing" on
  compact maps shows role mix mattered there — different hosts and forms (pb/d5 notes).
