# S-48 — Paired two-orientation requests and seat pairing (D-015, D-022)

**Kind:** Solution · **Status:** built, off · **Ledger:** L19 (context) · **Last reviewed:** 2026-09-30

Make every live A/B block play each map in both starting layouts so arms pair exactly by (map, side, opponent,
layout); locally, always play both seats and pair by fixture.

## Where it lives
- Lineages: hub executor protocol v2/v2.1 (director); analysis proposals by Claude (20-game request) and GLM (id-parity
  fill); local panels (run_panel z1/gen both seats; ouroboros "always play both sides"; frontier A-seat term).
- Code / docs: `docs/findings/2026-09-28-director-decisions.md` D-015, D-022 (+addendum), D-017; `docs/hub/PROTOCOL_V2.md`;
  `docs/findings/2026-09-28-analysis-claude-Q3-layout-parity-rule.md`, `…-Q2-paired-contrasts.md`;
  `docs/findings/2026-09-28-analysis-layout-assignment.md`.

## What it computes / does
- A1-Q3: the starting layout is f(map, game-id parity) (446/446 games); ids in one request are consecutive, so a
  10-map batch has one layout — two arms paired only when their first ids shared parity.
- D-015: one 20-game request per arm listing `M0..M9, M1..M9, M0` → 20 exact pairs per block; screens 3 × 20 = 60 pairs.
- D-022: the server creates one game per *distinct* map, so the request became two back-to-back waves (maps, then maps
  rotated by one), fills paired and parity-aligned; `max_fills 3`, `min_pairs 10`.
- GLM alternative: count ids and insert one filler game to flip parity (~1 game per block).

## Verdict and why it stopped
- Verdict: built and deployed (D-015, D-022); off since the executor went to shadow (D-031, 29 Sep 12:50 UTC). Local
  seat pairing is in use in every lane panel.
- Why it stopped: D-031 — "no automated uploads, game requests or activations while the teammates own the submission
  interface" (lead's instruction). The audit at 28 Sep 12:00 records "No confirmation has ever opened; no promotion has
  ever happened"; no later v2.1 confirmation is found (d1 notes). The D-015 falsifier (fewer than 20 exact pairs per
  block) was triggered by the D-022 incident and fixed; no block after D-022 is recorded.
- Host flag: host-independent (request shape); resumption is a mode switch (`hub-state/control/mode.json` → `live`).
- Revival condition: D-031's switch back to `live`; L19 (0.6) dev-545 proxy can only be tested then.

## Discrepancies
- Claude's "20-game layout experiment" vs GLM's id-parity fill: GLM calls the 20-game experiment "obsolete"; D-022
  shows the server does not honour repeated maps in one request, so the deployed form is two waves, neither proposal
  as written (d2 notes).
