# F-43 — Efficiency ledger and leak classes (C1-C; r3_ledger)

**Kind:** Feature (analysis) · **Status:** in use · **Ledger:** L05 · **Last reviewed:** 2026-09-30

A material ledger per map and cohort — pearls per 100 dragon-turns, moves per pearl, length per pearl — and length lost by leak class (newborn, trapped, portal, crowd23) in rounds 0–99.

## What it computes
- Computation (over F1 parquets): pearls/100dt, moves/pearl, len/pearl, death-len/pearl, sprint/pearl (len/pearl + sprint/pearl = 1 exactly: "|len/pearl + sprint/pearl − 1| max = 0.0000"); length lost per 1k dt r0–99 by class — newborn (child died ≤ 10 rounds of birth), trapped (enclosed at death: ≤ 15 cells in 5 steps, bodies blocking — [F-10](F-10.md); suicide excluded), portal (death head ≤ 2 cells of a portal; geographic), crowd23 (length ≤ 3 dying into own-side bodies); plus disjoint causes. Cohorts: top 10, ranks 11–30, band 55–85, team 7 ranked/live, local bots. Classes overlap by design.
- CPU: offline.
- Consumers: [A-27](A-27.md) (leak rows in lane reports; r3/sciel/esquie ledgers), P-entry measurements. No bot consumer.
- Evidence it matters (as an instrument): the falsifier (team-7 statistics outside band IQR) fired on 4/54 pooled statistics, 35/54 on Portals; reading "deficit is not income, not effort — it is death-side". Pooled length lost r100: top10 51.4, band 49.2, team 7 live 53.0. It set the C1-C fix list (never executed by C1-C; later by C1-F/R-3), and R-3 showed Ares V06 carries the same profile (trapped 36.1, newborn 19.3, portal 6.3, crowd23 11.4).
- Flags: overlapping classes; newborn class counts siting and churn together ("first-pearl lag median 5 rounds … newborn leak is siting, not search speed").
