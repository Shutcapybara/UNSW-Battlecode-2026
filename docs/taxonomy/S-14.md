# S-14 — Portal route handoff at split (ares-v33)

**Kind:** Solution · **Status:** local hold · **Ledger:** — (d1: candidate row the ledger lacks; L33 instance) · **Last reviewed:** 2026-09-30

At a split the parent sends the newborn the nearest known portal edge (edge key + portal id, sonar packet type 9, all
four directions); the newborn accepts it at age 0–1, targets the reachable side, commits through the edge, and clears
the route after transit or 12 rounds.

## Where it lives
- Lineages: Ares teammates' line (GPT/Codex) ares-v33-split-portal-route-handoff (parent V32); live submission v89
  (ID 12584, reported active). Ares C++, production line — the current live head.
- Code / docs: `docs/findings/2026-09-30-ares-v33-split-portal-route-handoff.md`; `bots/ares-v33-*/`; packet types in
  the Ares lineage: 7 = split handoff, 8 = HOLD ([S-17](S-17.md)), 9 = portal edge handoff.

## What it computes / does
- Trigger case: live match 658574 — the child moved east while the parent had already seen portal 1's entry edge; the
  child later saw the far-side pearl but never used the portal.
- One endpoint only (enough to route even when the pair is not fully learned). Route commitment is a two-state
  behaviour (route / normal) with a 12-round timeout.
