# S-24 — S1 swarm dissolve and density gossip

**Kind:** Solution · **Status:** reject · **Ledger:** L18, L15, L33 · **Last reviewed:** 2026-09-30

The S1 generation: build a large swarm early (λ_unit production to ~r100), then from a clock onset have small dragons
escort the crown and dissolve (die adjacent, recipient-eats-first) into it; share density between dragons by sonar.

## Where it lives
- Lineages (all Python on ouroboros-v10-beacon host): kazuha-s01, sakura-s01, chaewon-s01 (+ arms), yeji-s01/s01p
  (→ s02–s07), gpt-eunchae-s01..s06. Related density-messaging consumers: MC v06–v07, drake v08–v11, javert x02/x03,
  feynman F1, gaia v42–v63, von-neumann INFO arms.
- Code / docs: `docs/findings/2026-09-28-{kazuha,sakura,chaewon,gpt-eunchae}-s0*-swarm-dissolve.md`;
  `docs/findings/2026-09-28-director-S1-evaluation.md`; yeji READMEs; D-005, D-016.

## What it computes / does
- Production arm: SPLIT 2 toward a unit target (64; eunchae 40/48/60; sakura max(18, NC/24)) while λ_unit > 0 (full to
  r100, decaying to 0 by r380), crowd/danger gates relaxed in the opening.
- Dissolve arm: onset r300 on Slithery/Portals (map signature by dimensions) else r400; L ≤3 dragons within 30 escort
  the crown and dissolve only when adjacent and the recipient eats first. Crown election from r250 with id stagger.
- 2×2 design: production × dissolve.

## Verdict and why it stopped
- Verdict: reject on the Python ouroboros-v10 host (four lineages, seeded panels). Never tried on Ares.
- Why it stopped: "H-dissolve is falsified everywhere ... escort/dissolve path costs foraging turns and the r300 onset
  loses Portals and Slithery Fight" (director); "production is pearl-limited, not rule-limited"; "The S1 hypothesis is
  closed on the v10 host" (D-016); ledger: "gossip measured negative for early economy consumers" (L18).
- Revival condition: L18 (0.15) — "revives as a *late* consumer (L15) only"; L33 generalises it to mode beliefs with the
  Sciel/S1 lesson "consumers must be few and late-acting; no packet may drive an early economy decision". Host mismatch:
  the v10 host was later shown weak held-out (0.18–0.23 vs yuna-v03 0.42, yeji), so the S1 verdict is host-specific.
