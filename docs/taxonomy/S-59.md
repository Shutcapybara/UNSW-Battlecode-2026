# S-59 — Doom memory vs exact simulation (ouroboros, kraken, hydra)

**Kind:** Solution · **Status:** dropped · **Ledger:** — · **Last reviewed:** 2026-09-30

Two answers to wall/kelp and dead-end deaths: a persistent "doom" memory of corridors that killed allies (shared by
sonar), versus stepping every candidate path exactly through known terrain and bodies before scoring it. The memory was
zeroed; exact simulation became the converged architecture.

## Where it lives
- Lineages (Python): ouroboros v01–v05 (`w_doomed`, K_DOOM broadcast, `w_tunnel_unknown`, doom() dead-end search);
  kraken-v05-safety (doom map: ally seen in inner 5×5 last round and gone now → mark cell w_doom 500, approaches 120, for
  200 rounds; ablation x04-nodoom); hydra macro-spec (doom planned) and hydra-v11-macro (exact candidate simulation).
  Exact simulation is also the Tyr/yuna/Ares move scorer (DEAD → −1000 − steps).
- Code / docs: `docs/ouroboros-macro-spec.md` §1.3 (table row "Zero wall deaths come from doom memory"), §4;
  `docs/kraken-macro-spec.md` S4/S5, L265-266; `bots/kraken-v05-safety/README.md`; `bots/ouroboros-v05-spread/README.md`;
  `docs/family-comparison.md`; `bots/hydra-v11-macro/README.md`.

## What it computes / does
- ouroboros K_DOOM: a dragon with no non-doomed move reports the first corridor cell after its last junction; allies pay
  w_doomed 8 for 200 rounds. `w_tunnel_unknown` penalises known tunnels running into unseen tiles.
- kraken-v05 doom memory (per kraken-macro-spec S5), bundled with probabilistic strike pricing, exit counting, traffic
  terms.
- Exact simulation: each candidate path stepped through known terrain, bodies and vacancy; dead outcomes scored as death.

## Verdict and why it stopped
- Verdict: doom memory dropped (weight 0; no measured win of its own); exact simulation accepted — "converged
  architecture per all four reviews" (d5 notes) and in the production line.
- Why it stopped: ouroboros-macro-spec — "**Wrong attribution.** They come from exact candidate simulation: every path is
  stepped through known terrain and bodies. `w_doomed` has been 0 since late v05"; doom listed among "Feature families to
  prove or delete: tunnel memory, doom …" (§4) — no ablation table found (d5 notes). kraken — "no single component
  (trade/ini/exit/doom/p_strike) carries the drop"; planned kraken-v06 never built. hydra doom: planned, never built.
- Host flag: Python hosts. On the production line wall/kelp deaths remain (Ares V06 wall 7.7/1k; kelp 7.1/1k at V04;
  top ten median 0) despite exact simulation — the residual is attributed to trapped/cramped geometry, not missing
  simulation ([S-02](S-02.md), [S-07](S-07.md): "a navigation leak … not a scoring leak").
- Revival condition: none on the ledger. L33's warding (a dragon in a narrow pocket lowers neighbours' probability of the
  same mode there) is the ledger's nearest form of shared "don't go there" memory.
