# S-01 — Hard open-room filters and reach priority

**Kind:** Solution · **Status:** reject · **Ledger:** L24, L20 · **Last reviewed:** 2026-09-30

Restrict move choice to candidates whose post-move room (time-aware flood) or five-step body-blocked reach clears a
threshold, ignoring tighter moves even when they eat; a hard filter rather than a score term.

## Where it lives
- Lineages: Ares C++ teammates' line (GPT/Codex) ares-v10, v13, v14 (parent V09); robert-v02 (parent robert-v01 = V09
  profile); Renoir lane `ra` renoir-12a/12b (min room 5→8 / 5→12, on V06 atlas-off).
- Code / docs: `bots/ares-v10-open-room-priority/README.md`, `bots/ares-v13-enclosure-reach-priority/README.md`,
  `bots/ares-v14-enclosed-only-escape/README.md`, `bots/robert-v02-trap-pearl-gate/README.md`;
  `docs/findings/2026-09-30-ra-lane.md` table row 12a; `docs/BASELINES-2026-09-30.md` §Avoid.

## What it computes / does
- **ares-v10** (base V09): if any legal move leaves room ≥ full post-move length, choose only among those. A first
  version demanded extra slack; threshold then cut to full post-move length.
- **ares-v13** (base V09): benchmark-aligned probe — cells reachable in 5 steps with bodies blocking; >15 = open; if any
  candidate is open score only open ones; if enclosed and none clears, take max reach.
- **ares-v14** (base V13): apply V13's open-room priority only while the dragon is already enclosed (≤15).
- **robert-v02** (base robert-v01): hard-reject moves whose post-move room cannot fit the body unless the trapped room
  holds ≥3 reachable pearls; broader "room below growth-area target" form also tried.
- **renoir-12a/12b** (base renoir-00 = V06 atlas-off): minimum room 5→8 (12a) / →12 (12b).
- All hosts are Ares C++ (V06/V09 descendants) — the current production line.

## Verdict and why it stopped
- Verdict: reject on Ares C++ (production host). All Ares/Robert screens are 20 games vs one opponent (below
  BENCHMARKS resolution); Renoir 12a is a seeded 80-side-game screen.
- Why it stopped: V14 README — "hard escape selection was too disruptive"; V13 — "applying open-room priority while
  currently safe blocks normal food routes"; V19 README summarises the family: "Soft reach-score versions either failed
  to change this critical hazard or reduced deaths at a substantial r100 retention and W/L cost" → switched to the
  split-based escape ([S-03](S-03.md)). Renoir: "Caution costs economy in this lineage"; BASELINES: "Hard open-room
  filters (Ares V10, V13, V15): pearls halved."
- Revival condition: L24 (0.5, esquie proposes 0.35) routes the hazard to split-based escapes, not filters; D-035 (4)
  "hygiene bought with caution costs economy one for one on this lineage" — a filter would need to change *which*
  pockets are entered, not how many (ra-lane). No revival trigger names hard filters. Host was the production line,
  so "wrong host" does not apply.

## Discrepancies
- Ledger L24 groups V15 (a soft cost, see [S-02](S-02.md)) with the hard filters in "V10/V13/V15 lost 6–14 with
  pearls halved"; V15's own README gives 6–14 and pearls 74.4 vs 134.0.
