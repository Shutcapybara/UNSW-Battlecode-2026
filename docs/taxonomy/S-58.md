# S-58 — Router (cx-b01/b02)

**Kind:** Solution · **Status:** reject · **Ledger:** L07 · **Last reviewed:** 2026-09-30

Per dragon per turn: time-aware arrival maps for own, enemy and ally heads, bed values as pearls eaten before the
enemy's earliest arrival, greedy multi-dragon bed assignment with spacing and hysteresis, and routing that treats paired
portals as route steps — a routing-and-assignment policy on the C++ cx chassis.

## Where it lives
- Lineages: cx-b01-router (± noatlas), cx-b02-router (± noatlas, CANDIDATE.toml) on anna-a02-chassis; branch
  `origin/cx/b`. Opus, C1-B.
- Code / docs: `docs/findings/2026-09-30-cx-b01-router.md`; params.hpp "C1-B router" block; project
  `claude/cx-b-status.md`; D-029.

## What it computes / does
- Terrain 2-core peel (dead-end trees with depth/id); own time-aware BFS, enemy multi-source BFS from heads seen ≤ 8
  rounds, one BFS per nearest 6 allies; bed value over horizon clamp(√NC, 20, 60) with 0.95/step discount; respawn gap
  observed → atlas class → default 24; greedy assignment (me + visible allies) × beds with 3-cell spacing, pair swap,
  1.3× hysteresis; de-convergence from allies' next-6-step paths; paired portal = route step if landing has ≥ 2 open
  sides and lies outside every tree; pearl-gated split at L4 into 2+2 before r200.
- Crowding rules (b01 v3: crowd penalty, split gate, bigger room need) were added and turned off.
- Host: cx chassis (C++ testbed at 0.44–0.47 of field median economy) — **not** the production line; Ares was never given
  a router.

## Verdict and why it stopped
- Verdict: reject vs the prompt bar ("(c) does not meet the lead's bar"), on the cx chassis.
- Why it stopped: D-029 — "**Routing is not the lever; survival is.**"; the finding — "Stop investing in routing breadth"; next = survival-first bot, ship atlas off. The pool gain came from the atlas (two thirds) and the
  Dilemma/Autarky/Slithery mill.
- **Host flag — measured on a non-production host.** The router ran on a chassis at 0.44–0.47 of field economy that
  "does not have the leaks" (D-029 addendum); L07's weight is explicitly "rejected on the wrong host or in the wrong
  form" (ledger log, 29 Sep 18:50). D-029 (4) ordered its parts (2-core dead-end peel, arrival maps, enclosure-aware room
  check) into Ares as `params.hpp` switches — not executed in corpus code (c1 notes).
- Revival condition: L07 (0.2) — "Revive if R-1 flattens before any wall *and* R-5 finds the target/route weights
  dominate: then test a router on Ares". R-1 found no wall (22 M unbounded); R-5 not delivered. Sciel's arrival-time
  collision finding ("The collisions are arrival-time", [S-22](S-22.md)) is a further argument for arrival maps on Ares.
