# A-04 — Move scorer (candidate paths × terms)

**Kind:** Algorithm · **Status:** in use · **Ledger:** L04 · **Last reviewed:** 2026-09-30

One linear evaluation, in length units, over exactly simulated candidate paths (single steps, gated 2–3 step sprints, dives, head-ons), competing in the same argmax with split options.

## Where it lives
- Lineages: SIN chassis (sinbad v01–v07 → serre, fafnir, newton, fermi, witten, scholze, ed, ein-dog, odin), MC chassis (monte_christo → gavroche → vicious; fenrir → gaia; tyr, doug), yuna, bifrost, skadi, heimdall, loki (+0.5×GBT), Ares V03–V33 and descendants (Tyr V12 port); ouroboros v01–v13 (own evaluator), leviathan-v08/v09/x03 (transplant), kraken (inside a split→strike→move ladder), hydra-v11.
- Code / docs: `bots/ares-v06-expanded-search-support/policy.hpp:1310-1334` (candidates), `:986-1035` (simulate), `:1336-1410` (score); `bots/yuna-v00-control/policy.py` `rank_actions`; `bots/sinbad-v07-divecap/policy.py:L316-L452`; `bots/ouroboros-v13-ladder/evaluate.py:L51-240`, `defaults.py:L11-114`.

## What it computes / does
- Status scores (V06): DEAD −1000−steps; DIVE `dive_base` −0.5 − `p_dive` 0.1·dragon_value (+0.5·dive_value if the dive is the target, −½ threat); H2H strike ([A-11](A-11.md)) or −950 (enemy) / −1100 (ally).
- OK terms: goal `goal_weight` 1.2·(±1 on a shortest route)·(1.0 single / 0.7 multi-step); material lv·Δlen − `sprint_cost` 1.0·(steps−1), lv 1 before `grow_from` 380 → `lv_end` 3 over 120 rounds, crown 4.0, `material_unit_value` 3; eat bonus +0.5/pearl; blind landing −blind_risk·dragon_value; devil terms; escape bonus ([A-09](A-09.md)); crown flank −`w_flank` 3.0; threat −threat_cost; crowd −`crowd_weight` 0.6·(3−d) per ally head within tdist 2; revisit −`visit_weight` 0.15·visits; momentum +`momentum_weight` 0.6·EWMA (`momentum_decay` 0.6); bed block −`w_bed_block` 0.5; trap `trap_weight` 30·(need−cells)/need (+30 if cells < body) × dragon_value/`trap_value_reference` 8, ×`trap_farm_factor` 0.15 for farm pockets; need = max(len+`slack` 3, `min_area` 5), long bodies +len/3 capped `flood_cap_long` 40 (late 24, sparse 32), else `flood_cap` 24; `flood_credit` 2 / `flood_portal_credit` 6.
