# S-54 — Teacher-ranker (loki-v01/v02)

**Kind:** Solution · **Status:** reject · **Ledger:** L27, L16 · **Last reviewed:** 2026-09-30

Keep a host's hand-written candidate menu and add a small learned score that ranks the menu toward what a strong field
team chose in the same situation.

## Where it lives
- Lineages: loki-v01 (uploaded 8751), loki-v02-teacher-ranker, heimdall-v08-teacher-tiebreak — all on bifrost-v01
  (Python).
- Code / docs: `docs/loki-family.md`; `bots/loki-v02-teacher-ranker/{loki_ranker.py, trained_model.py}`; `tools/loki/`;
  `experiment_data/loki-v01-teacher-ranker/`; `experiment_data/team_recon_7_20260927T173904Z/REPORT.md` §"The newer
  Loki upload"; `docs/heimdall-family.md`.

## What it computes / does
- Teacher: team 龙虎豹 submission #7771, side A, 10 ranked replays. Bifröst's menu covered 99.5 % of teacher actions
  (136,069 of 136,760); 28,931 decision groups.
- Model: 48 depth-2 gradient-boosted trees over 28 actor-local features (no hidden enemy lengths, no sonar), 13 KB
  stdlib inference; score added at scale 0.5 to Bifröst's action score.
- v02: same model; cached geometry, sparse 6-feature extraction, tail-index simulation, safe pruning (2,000-menu argmax
  check).

## Verdict and why it stopped
- Verdict: reject on the Python bifrost/heimdall hosts; v01 was withdrawn after live runtime failure.
- Why it stopped: team_recon_7 — loki-v01 "fails its runtime requirement" (0–30 on CPU); L27 — "the ranker gain did not
  transfer across hosts" / "did not retain gains on the Heimdall host"; heimdall — "The Loki model in v08 did not help
  against Fenrir"; loki-family — v02's worst turn 94.1 M "so CPU faults were eliminated in these logs but worst-case
  headroom remains small".
- **Host flag — stopped by a CPU limit that C++ removes.** v01's live result is a runtime failure, not a policy
  measurement; the gain it showed natively (47–13) was never tested on a host with headroom. The transfer failure
  (Heimdall) is a separate, policy-level reason.
- Revival condition: L27 (0.5) — single-decision learned component exported to C++ on Ares, measured on that
  decision's ledger row; L16 (0.5, long-run) weight-table distillation.

## Discrepancies
- GLM's team-7 recon notes the 30 live games "were unranked vs own dev-test accounts in a 3-minute window" (d4 notes);
  the 0–30 is still a CPU-failure count (336 events), not a strength estimate.
