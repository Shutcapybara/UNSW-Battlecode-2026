# P-08 — Opening-vs-late trade-off (phase bifurcation)

**Kind:** Problem · **Status:** open · **Ledger:** L03, L02, L01, L21 · **Last reviewed:** 2026-09-30

The same algorithm change makes the opening worse and the late game better (or the reverse); because compact games are decided by r100, an opening loss is rarely recovered, and a four-checkpoint economy gate cannot credit a late-only gain.

## Where it lives
- Lineages: Ares V06 (search profile), lune-r1-01..08 (R-1 ladder), Python hosts under the CPU wall (yuna x37/x38, sakura-s02, tidus).
- Code / docs: `docs/findings/2026-09-30-r1-search-ladder.md`; `docs/findings/2026-09-29-ares-v06-expanded-search-support.md`; `docs/analysis/C1-pace-targets.md` Reading 7; `docs/analysis/ATLAS.md` Q1; `docs/hub/HYPOTHESES.md` L03.

## How it is measured
- Per-checkpoint economy deltas vs parent — pearls@50/100/150/250 ÷ field map median ([F-40](F-40.md)) — read separately rather than as the mean of four, plus dragons/length@100 and win share on the scorecard ([F-49](F-49.md)).
- Phase decisiveness from the field: winner − loser units/pearls at r50/r100 by map class ([F-47](F-47.md)); win share behind vs ahead at r100 (ATLAS Q1, [F-50](F-50.md)); HMM phase boundaries ([F-45](F-45.md)).
- Three-number form: not given for the trade-off itself. For the V06 base on the pool: p@100 0.94–1.03 of the top-ten median at field pct 0.55–0.60; dragons@100 0.96–1.04 at pct 0.59–0.66 (r1 §Step 0).
