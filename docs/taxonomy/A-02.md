# A-02 — Bounded target search

**Kind:** Algorithm · **Status:** in use · **Ledger:** L01, L25 · **Last reviewed:** 2026-09-30

A single value-bound-pruned BFS from the head that scores pearl, bed, unseen and dive cells by `cell_value·γ^t` under node caps, with hysteresis, far-target and hunt fallbacks.

## Where it lives
- Lineages: Ares V02–V33 (Tyr V12 port) and all V06 descendants; Python SIN/MC hosts (sinbad `choose_target`, gavroche, yuna, tyr, fenrir, bifrost …); ouroboros `choose_target` (goal field, `bfs_cap` 180); kraken BFS compass (`bfs_cap` 450; v01 600); leviathan (180 target cells). anna/cx use a different two-pass cost search ([A-20](A-20.md)).
- Code / docs: `bots/ares-v06-expanded-search-support/policy.hpp:1143-1151` (cap), `:1159-1167` (vmax), `:1175-1225` (loop), `:1181` (value bound), `:1186-1197` (dive), `:1230-1246` (hysteresis/far/hunt), `:801-826` (sector_target, far_target); `bots/yuna-v00-control/policy.py` `choose_target`; `bots/ouroboros-v13-ladder/targets.py:L29-131`; `bots/kraken-v05-safety/main.py:L744-845`.

## What it computes / does
- Cap order (V06): `cap = age<2 ? search_cap_born 60 : search_cap 160`; min with `search_cap_saturated` 64 when units ≥ 0.7·limit; `rnd ≥ search_cap_late_from 40` → min(cap, `search_cap_late` 48); `age≥2 && rnd≥search_cap_sparse_from 150 && units≤search_cap_sparse_units 20` → max(cap, `search_cap_sparse` 64). The 160 cap therefore applies only in rounds < 40.
- Early stop when `t > frontier_search_depth` 4 and `vmax·γ^t ≤ best`; `target_gamma` 0.93. Unpaired portal edges are dive candidates (`dive_value` 3, ×0.15 if an ally head is nearer). Fallbacks: previous target ×`target_hysteresis` 1.25; far_target (best remembered pearl by memory_value·γ^tdist, else nearest 8×8 sector with unseen cells); hunt ([A-14](A-14.md)). Valuation of each cell is [A-03](A-03.md).
- Varied (C++): ares-v06 72→160 with born 60 / saturated 64; ares-v09 / robert-v01 256/96/80, frontier 6, flood 32/48; lune-r1-01/02/03/04 ×2/×4/×8 (320/640/1280; late 96/192/384; sparse 128/256/512); lune-r1-07 late 384, sparse 512 only; lune-r1-08 late/sparse 100000; lune-r1-09 every cap 100000, frontier 1000 (CPU probe); esquie-* inherit 384.
- Varied (Python): sinbad v02 1,500 → 160 ("v01's 1500-node searches exceed the 100M-point turn limit"); yuna-x37 64, x38 96; gavroche v35 sat 96, v36 sat 64, v51 32 from r0; tyr-v12 72/40/48, v13 64/32/40; the-goat-v04 128/40; fenrir v13 frontier 3→4; yeji-s05 young caps 90/120.
- Never varied: `search_cap_late_from` 40 (R-1 names it the next knob), `search_cap_sparse_from` 150, `search_cap_sparse_units` 20, saturation fraction 0.7 (hard-coded 7/10), sector size 8, waypoint rule 3·tdist+steps, the ally-nearer dive discount, the vmax rule.
- Dead: `search_depth1` 16 (anna leftover; ares-v09/robert README lists 16→20 as a change — no-op).
- CPU: V06 p99 7.4 M, max 8.6 M; L0 max 8.52 M, L3 9.31 M; all caps unbounded 22.42 M (Big Empty B) — "The 100 M cap and the 60 M screening wall are not constraints on Ares's search" (r1 finding). vmax is an O(NC) memory scan every turn (`policy.hpp:1161-1164`).
- Dimension-keyed: sector count derives from W,H (`world.hpp:235-240`); no size thresholds in the search itself.
