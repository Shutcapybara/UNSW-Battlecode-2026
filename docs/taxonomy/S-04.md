# S-04 — Split-size salvage variants

**Kind:** Solution · **Status:** reject · **Ledger:** L24 (wave 2 not absorbed) · **Last reviewed:** 2026-09-30

Change the *size* (and admission) of the split a trapped or farming dragon makes — upgrade to the largest safe tail
child, room-fit both halves, gate by farm / portal topology — on top of V19's critical-enclosure split.

## Where it lives
- Lineages: Ares teammates' line (GPT/Codex) ares-v21 … v27 (parents V19/V23/V24/V26). Ares C++, production line.
- Code / docs: `bots/ares-v2{1..7}-*/README.md`; summary in `docs/findings/2026-09-30-ares-v28-minimum-sacrifice-enclosure-split.md`.

## What it computes / does
| Variant | Parent | Change |
|---|---|---|
| v21 critical-split-salvage | V19 | in critical state also replace a smaller routine split by the tail escape split (child len−2) |
| v22 room-fitted-split-salvage | V19 | if a size-2 split leaves the parent below room need, take the smallest larger child where both halves meet forecast room |
| v23 farm-gated-salvage-split | V19 | when best move is a pearl-rich farm in an under-room pocket and a smaller split is chosen → upgrade to largest safe tail child |
| v24 established-farm-salvage | V23 | V23 only for established dragons (escape inactive) |
| v25 nonportal-farm-salvage | V24 | salvage child needs an immediately open non-portal exit |
| v26 critical-farm-salvage | V23 | farm AND reach ≤8 AND not newborn-escape |
| v27 no-portal-farm-upgrade | V26 | apply upgrade only when no portal edge is known (atlas or remembered edge grid) |

## Verdict and why it stopped
- Verdict: reject on Ares C++ (production host), all at 4–20-game one-opponent resolution (directional only per the
  ledger's teammate procedure).
- Why it stopped: V28 finding — "These versions either generalized the largest-child upgrade too broadly or gated it
  [too narrowly]"; the line turned to the opposite direction, minimum sacrifice ([S-05](S-05.md)). Motivating live
  complaint: tyr-v01 loss review "kill two and let the rest escape, rather than killing three"
  (`docs/findings/2026-09-29-tyr-v01-live-loss-review.md`).
- Revival condition: none stated. d1 ledger reconciliation notes wave 2 (V21–V33) never received (T) rows despite
  the ledger's own procedure. Python analogues (yuna x25–x27 child L−2 −2/−1.5/−1; vibing split-size graft 4–8,
  [S-36](S-36.md)) also found little surface for split-size changes.

## Discrepancies
- v27 gates on "atlas or remembered edge grid"; the atlas is dead code in the V06 lineage (`atlas_try()` never called),
  so only the edge grid was active (inferred, d3 notes).
