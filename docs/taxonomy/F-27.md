# F-27 — Learned-feature vectors (m01 features_view, Loki features, clone-62 v4 features, team-recon v4)

**Kind:** Feature · **Status:** in use in learned opponents only (m01, clone-62); dead in hosts (risk_features) · **Ledger:** L16, L27, L34 · **Last reviewed:** 2026-09-30

Fixed-length vectors computed from a dragon's legal view and memory, used as model inputs for imitation, ranking or hazard models.

## Where it lives
- Lineages / forms: ouroboros-m01/m01p `features_view.py` (behavioural clone of team 306); loki-v01/v02 `loki_features.py` (28 features; heimdall-v08 reused); clone-62-v01 (258 v4 view+mem features) on `origin/sakura/s02`; team-recon v4 legal-view namespace (`tools/team_recon_claude`, codex, GLM `vibing_lib.py`); MC v02–v05 hazard features (`risk_features.py`, 13 features), carried unused into gavroche, vicious, fenrir, gaia, yuna hosts.
- Code / docs: `bots/ouroboros-m01-vibing-mimic/features_view.py` (L150-153 writes W, H, x, y, xn, yn, n_msgs); `bots/loki-v02-teacher-ranker/loki_features.py` L8-18; `origin/sakura/s02:bots/clone-62-v01/README.md`; `bots/yuna-v00-control/risk_features.py`; `experiment_data/team_recon_306_20260927_claude/REPORT.md`.

## What it computes
- m01: round, length, units, W, H, x, y, facing, n_msgs, 5 echo counts ([F-19](F-19.md)); ego-rotated 7×7 occupancy/pearl/countdown grid; visible counts; nearest pearl/enemy/ally; per relative move F/R/L/B: block code, portal, pearl, in-window BFS area, pearl mass, allies/enemies within 2, straight run; own memory (age, since split, since eat, revisits …).
- Loki: 28 features (round, length, unit fraction, age, width, height, open_exits, split_fraction, move_steps, relative_direction, survival, end_exits, …); the 48 depth-2 trees split on only 6 of them.
- MC hazard: step2/3, longer/equal, own/enemy length, cut, later_id, round, units, multi_threat, compact = cells ≤ 625.
- CPU: loki-v01 93 CPU-limit events (sandbox), live 0–30 with 336 TLE turns; v02 sparse 6-feature extraction, max 94.1 M.
- Consumers: [A-23](A-23.md) learned/imitation components (m01 HGB 120×31, loki GBT ranker at scale 0.5, clone-62 HGB, MC fitted hazard → [A-11](A-11.md)). In hosts, `risk_features.py` is never imported — no consumer.
- Evidence it matters: m01 test accuracy 0.739 (majority 0.421; greedy rule 0.615; view-only 0.723; + privileged full state 0.738 "adds nothing"); same pipeline on ouroboros-v10's own replays 0.723 — "ceiling is our state representation and missing messages"; closed loop 51–53 on the zoo; under-produces (units r100 15 vs teacher 22). Loki top-1 teacher action 64.1 % / 70.3 % vs uniform 21.9 / 23.2 %. clone-62 test accuracy 0.804, profile z ≤ 0.94 (accepted as a local opponent). MC hazard "Predictive loss improved, but this did not establish general playing strength"; fitted table had 8, 13 and 0 examples in three of nine classes.
- Flags: dimension-keyed inputs (W, H, x, y in m01; width/height in loki, unused by the fitted forest; `compact` in MC). Dead: `risk_features.py`, `diagnostics` (training_trace 0 everywhere). m01 `model.json` / `params.json` absent from the corpus — the model cannot be inspected.
