# F-05 — Bed timing (bed/spawn_at, bed_wait=0, bed_stale, bper false-fast, respawn-gap memory)

**Kind:** Feature · **Status:** in use (bed_wait=0 branch unreachable in V06; `bed_wait_max`, `bed_tie` dead) · **Ledger:** L11 · **Last reviewed:** 2026-09-30

Which cells are pearl beds and the predicted round each bed next produces a pearl, from visible countdowns; some lines add a period estimate or an observed respawn gap.

## Where it lives
- Lineages: all planning bots. Variants: host `bed[c]`/`spawn[c]` (SIN/MC, yuna, tyr, bifrost…); ares-v01..v33 `bed[c]`/`spawn_at[c]`; `bper` period bound (sinbad-v07, spike-x10, tidus, skadi-v11, witten-x02; reset-qualified in witten-x03 `bed_cycle.py`); vicious `PERIOD[c]`; gaia BED_OBS; yeji-s06 `online_beds` (fast ≤ 40); cx-b02 respawn-gap memory (`gap_obs`, `gap_sum/gap_n`, `bed_first_pearl/n`); ouroboros spawn window; leviathan-v09 arrival rule; hydra-v11 re-arm r+14.
- Code / docs: `bots/ares-v06-expanded-search-support/world.hpp:95-96`, `:357-363`; `policy.hpp:737-750` (bed branch), `:160-165`, `:1391` (w_bed_block), `:628-629` (gossip horizon 30), `:1163-1166`; `bots/cx-b02-router/world.hpp:90`, `:214`, `:330` (`gap_obs`); `bots/tyr-v01-yuna-momentum/policy.py` L52-55; `bots/spike-x10-v32-wellvalue/params.py` L48-50.

## What it computes
- Computation (V06): `bed[c]` 0 unknown / 1 bed / −1 not; `spawn_at[c]` = round the next pearl appears. cell_value: with bed_wait = 0.0 only beds ripe by arrival count (bed_value 8); past-due-but-unseen beds decay linearly to 4 over bed_stale 60 then 2.4. Host (bed_wait 12): future beds valued v_bed·(1 − (s − arr)/bed_wait). `bper` = largest countdown seen (an upper bound on the gap). cx-b02: per-bed last observed respawn gap, falling back to mean, atlas class, then 24; later ripenings weighted 0.3.
- CPU: O(view) per turn; cx-b02 value sums over a horizon per bed (router p99 ≤ 11.7 M).
- Consumers: [A-03](A-03.md) (bed branch, `have_bed` → vmax in [A-02](A-02.md)), [A-04](A-04.md) (w_bed_block −0.5 for standing on a bed one round before spawn), [A-09](A-09.md) escape resource value, [A-12](A-12.md)/[A-13](A-13.md) (future beds gossiped within 30), [A-19](A-19.md) (router bed value and patrol timing, cx-b02 only), [A-14](A-14.md) (hunter-v20 hotspots: beds due ≤ 8).
- Evidence it matters: the arrival predicate is among the largest opening effects measured in Python: sinbad-v06 compact vs other pool 13–19 → 25–7; leviathan-v09 arrival on 22–8–0 vs off 15–14–1, opening pearls 16.23→23.07 (30 compact fixtures); fenrir-v18 (bed_wait 0) 77–43 vs 4 refs. Waiting on future beds measured negative on Ares: renoir-01a/c bedwait 4/16 −0.065/−0.058 (Devil −0.72, Schooltime −0.41; QoS +0.16, Trauma +0.14); renoir-11 idlebed −0.063; ra-08 bed_value 10 −0.0327. Supply-gated wait: esquie-03b LOCAL HOLD Δecon +0.0018 [−0.0024, +0.0062], Trauma win +6 pp.
- Flags: `bed_wait = 0.0` makes the future-bed branches in cell_value (:741-742) and escape_resource_value (:161-162) unreachable; `bed_wait_max` 0 and `bed_tie` 1 are DEAD (anna leftovers). `bper` false-fast: "the largest countdown seen, not a measured full respawn period; a slow bed first observed near spawning can have bper ≤ 5" — witten-x02 changed actions in all 4 arena games "despite arena having no fast beds"; fixed by reset-qualified cycle in x03 (competitively null). Respawn-gap memory exists only in cx-b02; not ported to Ares (grep: 0 files). hydra-v11 `bed_rearm_gap` param unread (r+14 hard-coded, world.py:L300). Dimension-keyed: bifrost-v15 bed_wait_compact_cells 625; tidus fast_edisc_nc 625 / nc_min 256.
