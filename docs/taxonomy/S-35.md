# S-35 — Pace controller (P1: pace-v01–v03, three authors)

**Kind:** Solution · **Status:** reject · **Ledger:** L17 · **Last reviewed:** 2026-09-30

A per-turn controller that compares the team's unit count with a field pace curve and pushes production (raise split
value) when behind and holds it when ahead.

## Where it lives
- Lineages: pace-v01, pace-v01-nolimit, pace-v02 (per-map curve), pace-v03 (no pocket-farm discount) on host
  chaewon-y04-probe (yuna-v05 lineage, Python). Three independent reports under one filename: main (Claude),
  `origin/glm/pace-v01`, `origin/pace/v01` (Codex).
- Code / docs: `docs/findings/2026-09-29-pace-v01.md`; `bots/pace-v03/pace.py`, params.py L155-176;
  `tools/pace/results/p1-results.jsonl` (1,226 games); `origin/glm/pace-v01:docs/findings/2026-09-29-pace-v01.md`;
  `origin/pace/v01:docs/findings/2026-09-29-pace-v01.md`; prompt `docs/hub/prompts/2026-09-29-P1-pace-bot.md`.

## What it computes / does
- Main: behind the class curve → split_val +1.5 per missing unit (cap 6) with survival limits (child room ≥6, no enemy
  reach, parent not trapped); ahead by ≥3 from r60 → split_val −10 (hold); below the r250 share from r100 → food ×1.3.
  Targets compact u25 6 / u50 9 / u100 18 / t250 80, open 6/11/19/100. nolimit drops the survival limits.
- GLM: corpus winner-median targets; split_val +7×deficit, opening window extension, food ×(1+gain×deficit),
  approach-only 2-step sprints.
- Codex: corpus zero-filled medians (460 replays), open r100 15, compact 13.
- Host: Python — not the production line.

## Verdict and why it stopped
- Verdict: reject on the Python yuna-lineage host, all three authors; main: "Do not register pace-v01 for screening".
- Why it stopped: "**Production is pearl-bound, not decision-bound.** Units ≈ total/2.3 throughout the opening; the
  host already splits" (main finding); "ACT:pace+ 9.4 per game in r0–100 … The push is inert (the host splits anyway);
  the hold is what changes games". GLM: "the deficit is death-limited, not willingness-limited"; "valuation-level
  production control cannot reproduce the field's curve". Codex: "missed the field curve, lost paired material and
  score, and failed both survival ceilings". C1-addendum: "No task tunes production for its own sake".
- Host flag: measured on a Python host at its CPU edge (p99 60.5 M); the stated stop reason is pearl supply, not CPU,
  so the C++ move does not by itself revive it (inferred). Never re-tested on Ares.
- Revival condition: L17 (0.1) — "revives only if a bot shows a pearl surplus at r50 (then production is the
  bottleneck)". Adjacent evidence not yet read as the trigger: r3-03's cramped split is "a production lever" (+5 pp win,
  L30, [S-06](S-06.md)); Sophie K-1: losing maps "are lost to opening economy and production"; uneaten bed pearls at
  r100 are plentiful (Schooltime 63, Portals 64, Trauma 56 — C1-addendum).
