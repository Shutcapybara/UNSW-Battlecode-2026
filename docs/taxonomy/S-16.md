# S-16 — Blind-exit occupancy memory

**Kind:** Solution · **Status:** hold · **Ledger:** L06 · **Last reviewed:** 2026-09-30

Price an out-of-view portal exit by recent sightings near it instead of a flat blind risk: floor 0.15 if surveyed
quiet, 0.5 if unseen, 1.0 if a body was seen near it within 12 rounds (× the dragon's value); yeji's variant charges
P(occupied) × (value + 2) from bodies seen in the last 4 rounds and fresh ally reports.

## Where it lives
- Lineages (measured only on Python hosts; present but never varied on Ares, where the Tyr port carries it as
  `blind_fresh 12 / blind_body 1.0 / blind_seen 0.15 / blind_unseen 0.15`, `bots/ares-v06-expanded-search-support/params.hpp:145-148`):
  - valjean-v01 (origin, on Monte Christo) → bifrost-v01 portal-exit memory → fenrir (blind_mem 1; r_unseen 0.5→0.15

  - skadi-v12 portal-exit memory, v13 clear-exit-only (gavroche-v54 host).
  - yeji-s02..s06 `w_blind_occ` (ouroboros-v10 host).
- Code / docs: valjean README; `docs/bifrost-family.md`; `experiment_data/strategy_leaks_20260926T225633Z/REPORT.md`

## What it computes / does
Per portal exit: a sighting window (12 rounds) and a three-level risk (0.15 / 0.5 / 1.0) replacing host p_blind 1.0
("host p_blind 1.0 starves portal maps", pa1 notes). Yeji: blind_body_mem 4, blind_body_p 0.5, blind_ally_p 0.3,
w_blind_occ 1.0.

## Verdict and why it stopped
- Verdict: accept on valjean/bifrost/fenrir (it is inside the Tyr lineage that Ares ports); inconclusive or below gate
  on witten, einstein, skadi, yeji. Never re-measured as a switch on Ares.
- Why it stopped: witten — "+1 matched gain misses the frozen +2 gate"; einstein — "pre-registered target gate failed,
  so transformed holdouts were not opened"; skadi — "The v13 holdout was not run, following the request to stop after
  this iteration". The Python era ended with D-029 (Ares as production, inferred).
- Revival condition: L06 (0.2) — exit-side, per-transit survival at unchanged volume. Blind-exit memory *is* an
  exit-side pricing term, but on the Python hosts it was measured as outcome only, never as per-100-step portal deaths;
  on Ares the equivalent lives in the ported Tyr code and was never ablated (inferred: no Ares switch in any lane).
  Host mismatch is a live reason to re-measure it on Ares with the C1-D walk ([F-44](F-44.md)).

  over-penalty" — i.e. valjean's gain partly measures removing p_blind 1.0, not the memory.
