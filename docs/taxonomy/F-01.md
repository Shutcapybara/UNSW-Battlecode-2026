# F-01 — Terrain edges, kelp and the dest table

**Kind:** Feature · **Status:** in use · **Ledger:** — · **Last reviewed:** 2026-09-30

Per-edge terrain memory (unknown / open / kelp / portal id) learned from the view each turn, and the cached per-(cell, direction) engine step derived from it.

## Where it lives
- Lineages: every host that plans on terrain — Python SIN/MC hosts (sinbad, serre, fafnir, newton, gavroche, yuna, tyr, bifrost, skadi, heimdall, loki, chaewon-y*, pace, spike, tidus, fenrir, gaia …), ouroboros/avery/drake (own world models), anna/cx chassis, ares-v01..v33 and every V06 descendant (lune, renoir, monoco ra-*, r3-*, robert, sciel, esquie).
- Code / docs: `bots/ares-v06-expanded-search-support/world.hpp:82-83` (`ek`, `epid`), `:132` ekey, `:157-176` dest table, `:246-270` learn_edge, `:365-388` sense loops, `:389` rebuild; `bots/yuna-v00-control/world.py` §sense, `_learn`, `_touch`; `bots/sinbad-v07-divecap/world.py` L92 ekey, L219 sense.

## What it computes
- Lineages: all planning bots; the C++ layout is a direct port of the Python host (Tyr ordering "horizontal grid then vertical grid" preserved).
- Computation: `ek[2·NC]` edge kinds 0 unknown / 1 open / 2 kelp / 3 portal, `epid` edge→portal id; key c = north edge of c, NC+c = west edge. Learned from the 8×7 horizontal and 7×8 vertical edge rows around the head. `dest_tab[4·NC]` caches the landing cell per (cell, dir) with sentinels BLOCKED −1, UNKNOWN −2, UNPAIRED −3. Unknown edges are optimistic (open) in planning (`step_opt`, world.hpp:178-181) but only credited, not traversed, in the room flood (policy.hpp:954-957).
- CPU: V06 rebuilds the whole dest table (O(4·NC)) when `dest_dirty` is set after any terrain change (sense, and hear_radio policy.hpp:508). The Python host's `_touch` invalidates only the two cells beside a learned edge; `docs/strategy-backlog.md` L140 records an earlier whole-cache invalidation on portal pairing that caused CPU spikes on portal maps. cx-b02 adds a `dest_version` counter to cache its 2-core peel.
- Consumers: [A-02](A-02.md) target search (`step_opt`), [A-04](A-04.md) move scorer (`simulate`, kelp-count terms of r3-04 / cx-f04), [A-08](A-08.md) enclosure reach, [A-09](A-09.md) newborn `topology()` probe, [A-10](A-10.md) portal handling (UNPAIRED ⇒ dive), [A-19](A-19.md) router peel, [A-20](A-20.md) anna tiers; feeds [F-09](F-09.md), [F-10](F-10.md), [F-24](F-24.md).
- Evidence it matters: foundational; never ablated. The only measured term built directly on kelp counts is r3-04 (landing with <3 known-open edges −2.0): wall −27 %, trapped −30 %, econ −0.072 on Ares (`docs/findings/2026-09-30-r3-ares-leaks.md` §Step 3); the same idea on the chassis (cx-f04) "never flips a decision" (2/235/3).
- Flags: none dead. Not dimension-keyed beyond array sizing.
