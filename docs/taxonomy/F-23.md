## What it computes
- Computation (V06): age < 2 → search_cap_born 60; units ≥ 0.7·limit (hard-coded 7/10) → saturated caps (search 64, sprint3 4); rnd ≥ 40 → search cap 48; rnd ≥ 150 → sprint limit 5, flood_cap_long 24, sparse relief if units ≤ 20; r ≥ 200 hunting; r ≥ 250 crown machinery; r < 380 splits, lv ramp 380→500; opening production r 1..30 while units < 32; devil terms r < 42 / < 100. yuna phase uses global round, never age ("a child never restarts the opening").
- CPU: none; its main use is CPU budgeting.
- Consumers: [A-15](A-15.md) phase guards, [A-02](A-02.md) (caps), [A-05](A-05.md) (sprint limits), [A-06](A-06.md) (split window, opening production, units < limit), [A-14](A-14.md) (crown/feed/hunt clocks), [A-04](A-04.md) (length value ramp), [A-10](A-10.md) (yuna phase-scheduled portal policy), [A-26](A-26.md) (kraken child size by phase; ouroboros mixes), [A-24](A-24.md).
- Evidence it matters: lune-r1-07 (late cap from r40 48 → 384, sparse 512): econ +0.026, dragons@100 +0.053, length@100 +0.046, win −0.016 n.s. (seeds 1+2), gen econ +2.5 % — registered at priority 510 (D-034); the R-1 ladder shows wide search costs the first 40 rounds (−0.04 to −0.11 expected score) and helps late (p@250 +0.10–0.13) ([P-08](P-08.md)). yuna ph_t1 60 beat 120 (x21 −3): "Hard thresholds only were competitive". - Flags: hard-coded 7/10 saturation, crown 250, game end 500, lv ramp 120 rounds. doug's ID-population estimator never measured. `info_aggro_sat` 0.7 doubles as the Python CPU switch.
