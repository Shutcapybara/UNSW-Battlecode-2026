# A-08 — Critical-enclosure and cramped splits

**Kind:** Algorithm · **Status:** local hold · **Ledger:** L24, L30 · **Last reviewed:** 2026-09-30

Firing the escape split before every move is dead — when the five-step body-blocked reach is critical (V19 line, esquie-04) or the room flood is short of need (r3-03) — plus the size/defer variants built on it.

## Where it lives
- Lineages: ares-v13–v33 (teammates GPT/Codex), r3-03 / r3-05 (GLM), esquie-04 (V19 port on lune-07/nodevil); Python: skadi exit guards, bifrost v04/v29 net-growth farms, pace-v03 no farm, chaewon-s02 farm_min_region, hydra-v11 split pocket, robert-v02 trap-pearl gate.
- Code / docs: ares-v19 `policy.hpp` (`enclosure_reach`, diff vs v09); `bots/ares-v32*/policy.hpp` (`tyr_dead_end_split_child`); r3 carrier `policy.hpp` (`r3_escape_early`); `origin/r/esquie:bots/esquie-04*/policy.hpp:1440-1446`; `docs/findings/2026-09-30-r3-ares-leaks.md`.

## What it computes / does
- V13–V18 probe: `enclosure_reach` = cells within `enclosure_reach_steps` 5, body-blocked, occupancy static; open = > `enclosure_open_cells` 15; soft weight `enclosure_reach_weight` 0.35 (V15–V17) / 1.2 (V18); critical ≤ `enclosure_critical_cells` 8 (V16, V18, V19+).
- V19: current reach ≤ 8 and best move reach ≤ 8 → V09's tail escape split. V20: only if the best move does not raise reach. V21: upgrade routine split to escape split in the band. V22: room-fitted child size. V23–V27: farm-gated upgrades (established, non-portal, critical overlap, no known portal). V28: escape child = `split_child` 2. V29–V31: defer splits on under-room farm / dead-end feeding / immediate pearl. V32: largest child with exit + child_area room at a no-move dead end. V33: portal route handoff on split ([A-10](A-10.md)).
- r3-03: escape split when current room flood < `r3_escape_room_frac` 0.75·need, competing at `r3_escape_score` −10. esquie-04: `esquie_reach_steps` 5, `esquie_reach_critical` 8.
- Varied: activation band (≤15 / ≤8), weight (0.35 / 1.2), hard vs soft vs split response, child size (len−2 / 2 / room-fitted / largest viable), defer rules; r3 trigger (flood fraction).
- Never varied: reach horizon 5 steps (every version), critical threshold 8 for the split versions, r3 fraction 0.75 and score −10 (single values), esquie 5/8 (ported values), static-occupancy assumption of the probe.
- CPU: V19 computes `enclosure_reach` (`enclosure_blocked.assign(NC)` + O(NC) occupancy loop) for every OK candidate (up to 52) plus the current state; esquie-04 only when a candidate becomes best-so-far. V28 sandbox max 9.14 M; V19 8.78 M; r3-03 p50 4.7 / p99 7.3 / max 8.7 M.
- Hard-coded: open 15 and critical 8 thresholds are the C1-C benchmark definitions (≤15 enclosed, ≤8 critical).
- Dimension-keyed: V27 `map_has_known_portal` reads `w.atlas` first (always −1: atlas never populated).
