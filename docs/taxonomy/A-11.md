# A-11 — Threat and support model

**Kind:** Algorithm · **Status:** in use · **Ledger:** L09, L10 · **Last reviewed:** 2026-09-30

Expected loss from enemy heads that can reach a cell, discounted by size-matched ally support, plus the strike rule that turns a head-on into a positive-score move.

## Where it lives
- Lineages: SIN (sinbad v02+) and MC hosts, yuna, tyr (pearl-funded floor), skadi (Fafnir support arms), bifrost-v09/v12, fafnir f8–f12, fermi x01/x02, gavroche w_support, spike x11/x12, Ares V03–V33 (V06 adds support) and descendants; ouroboros head_risk (p_strike 0.75/0.35/0.15), kraken-v05 lethal/soft, hydra-v11, godel/VN aggression refits, MC v02–v05 fitted hazard ([A-23](A-23.md)).

## What it computes / does
- Danger map: every visible enemy head within Chebyshev 7 reaches clamp(len−1, 1, 3) steps through free cells.
- threat_cost(cell, L) = `threat_weight` 1.0 · max over threats of p·max(`threat_base` 1.0, V(ours) − `threat_enemy_loss_weight` 0.5·V(theirs)); p = `threat_long` 0.9 if we are longer, `threat_equal` 0.7, `threat_short` 0.1 if shorter; ×`threat_sprint_factor` 0.8 if >1 step; ×max(0.25, (1−`threat_ally_support` 0.25)^supporters), supporters = visible ally heads with visible length ≥ enemy length within `threat_support_radius` 3 of that enemy head (V06).
- Strike: into an enemy head with units ≥ `attack_min_units` 3: gain = V(their len) − V(our len) − sprint_cost·(steps−1) + 0.5·min(allies within 3, 2); strike if gain ≥ `attack_margin` 0.5 → 2+gain. Enemy length adds `cut_extra` 1 (prey +2) when running out of view.
- Varied (C++, econ~ Δ): threat_weight renoir-17a 0.5 (+0.012), 17b 1.5 (queued), 17c 0.25 (+0.016), 17d 0 (+0.019; seat-A screen +0.044), ra-11 0.70 (+0.0024, win −1.56 pp); attack_margin renoir-21a 0 (−0.039); support added in V06 (0.25, radius 3).
- Varied (Python): yuna-x28 w_threat 0.7 / x30 1.5 opening, x31 atk_margin 0 + w_support 1.0 (−4..−7); bifrost-v09 k_their_shorter 0, v12 multi_threat 0.5; skadi support 25 % (v02) / radius 2 (v04) / 35 % (v05) / 15 % (v06) / 10 % (v08) / collision tile (v10); fafnir self-centred (f8), attacker-centred (f11), size-matched (f12); fermi x01 per-attacker, x02 route; gavroche w_support +1 cap 2 (v32), half (v33), 0.75 (v65/v66), v40 threat-off probe; spike-x11 w_support 1.0 / x12 0.0; sinbad reach_cap_crown 6; tyr p_pearl_sprint 0.6 (v25) / 0.2 (v34); godel trade_bias 2.5, p_strike2 0.5; VN pacifist/berserk/aggro-off; kraken-v05 w_danger_base 120 / seg 60, hard_frac 0.55; ouroboros-v06 Lanchester.
- Never varied (C++): `threat_long` / `threat_equal` / `threat_short`, `threat_sprint_factor`, `threat_ally_support`, `threat_support_radius`, `threat_enemy_loss_weight`, `threat_base`, `attack_min_units`, `cut_extra`, `prey_cut_extra`.
- Hard-coded: danger radius Chebyshev 7 (`:877`), reach clamp 1..3 (`:887`), support floor 0.25 (literal in `:1058`), strike support radius 3 and +0.5/ally (max 2), strike base 2.0, −950/−1100 sentinels, child-danger −1.0.
- CPU: one small BFS per visible enemy head within 7.
- Dimension-keyed: none.

## Status and open questions
- In use. "Aggression is a valid component to keep and calibrate defensively; it is not a dial to turn up" (godel). VN: "the binding constraint is contact creation (economy-driven), not trade admission". Local fight rules (L10) never built.
- Reading (c1, undocumented): p is highest (0.9) when we are longer, i.e. it encodes "we lose more material when longer", not head-on outcome probability; docstring says "Opponents in the pool trade into LONGER targets".
