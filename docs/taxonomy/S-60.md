# S-60 — Look-ahead / reply search (hunter-v16–v19, leviathan Riptide/Charybdis)

**Kind:** Solution · **Status:** reject · **Ledger:** L01, L02 (context) · **Last reviewed:** 2026-09-30

Search beyond the one-turn candidate: multi-turn self-trap look-ahead, trap/boost tactics that need the enemy's exits,
beams over forecast bodies and pearls, and alpha-beta over the nearest enemy's replies.

- Lineages: hunter-v16-boost-traps, v17-portal-first-traps, v18-self-trap-lookahead, v19-safe-growth-lookahead (C++,

  Charybdis (C++). None on the Ares line.
- Code / docs: `bots/hunter-v16…v19-*/README.md`, hunter-v23 main.cpp:L992, L1077 (SURVIVAL_LOOKAHEAD 6);
  `docs/leviathan/RIPTIDE.md`, `docs/leviathan/CHARYBDIS.md`, `docs/leviathan/ESTUARY_BOT_HANDOFF.md`;
  `bots/leviathan-x02-riptide-viability/params.h`, `bots/leviathan-x04-charybdis-replies/params.h`.

## What it computes / does
- hunter-v16/v17 boost-trap: attack route ≤ 6 steps leaving the enemy head's three sides occupied, or a cutoff leaving it
  ≤ 1 exit; needs full visible enemy body, enemy not yet acted, 2 safe exits kept, size lead ≥ 4/≥ 3.
- hunter-v18/v19: 6-move look-ahead rejecting routes that end in a short pocket enclosed by our own body; per-first-step
  continuation depth.
- Riptide x01: per legal first action a beam of 8 states over 6 turns (forecast body, eaten set, discount 0.86); x02 adds
  an earliest-arrival viability flood. Estuary x03: node-bounded (120) depth-5 continuation existence search on long
  bodies (trap_cost 35).
- Charybdis x04: local game with own dragon + nearest fully observed enemy within 5 steps, exact id turn order, alpha-beta
  over 3 reply half-turns, width 6, node budget 450.

## Verdict and why it stopped
- Verdict: reject for promotion; Riptide x01/x02 "archived from mainline promotion; retained as an experimental search
  baseline"; Charybdis "retained for phase-end comparison"; hunter look-ahead inherited without its own measurement.
- Why it stopped: Riptide — compact opening production deficit not fixed (opening [0,30) 23.08 pearls / 6.17 splits vs
  opponents 37.83 / 13.50) and "forecast horizon adds no measured value (myopic equal)"; Charybdis — "mixed evidence for
  the reply-search hypothesis"; "evidence against this particular model/evaluator pairing, not against adversarial search
  in general"; Estuary — "Keeping the unproven veto enabled merely because it sounds safer would misrepresent the
  evidence"; hunter v21–v23 stop not stated.
- Host flag: Riptide and Charybdis are independent C++ chassis with weak base economies (compact 4–46 / 16–34), not the
  Ares line; Charybdis's node budget was cut 1,800 → 450 for CPU even in C++ because of accounting, later fixed (final max
  57 M). On Ares, search width was tested by R-1 ([S-31](S-31.md)/[S-32](S-32.md)) but no reply search or multi-turn
  look-ahead exists.
- Revival condition: L02 (0.7) selective depth — "Stockfish-style extensions/reductions keyed on local volatility (enemy
  heads in view …, contact distance)" is the ledger's form; C2-0's fight-cost gap is where a reply search would act.
