# P-22 — Local-to-live transfer and judge divergence

**Kind:** Problem · **Status:** open · **Ledger:** L19 · **Last reviewed:** 2026-09-30

Local win shares and ratings overstate live results for every mapped source and do not order candidates the way live play does; since ~12:30–13:08 UTC 27 Sep the public judge's message handling also differs from the local engine, so replay-driven reconstructions agree only ~92%.

## Where it lives
- Sources: live submissions 9508 fenrir-v18, 9663 yuna-v02, 9639 ein-dog-v02, 8540 bifrost-v01, 9980 tidus-t02, 10013 yuna-v03 (dev); local ledger (119k 1.0.0 games), adaptive ratings, frontier panel.
- Code / docs: `docs/analysis/ATLAS.md` Q4, Q8, Q10; `docs/findings/2026-09-28-analysis-claude-Q4-*`, `-Q8-*`, `-Q10-*`; `experiment_data/team_recon_7_20260928_claude/REPORT.md` §2, §5; D-010, D-017.

## How it is measured
- Live − local win share per source (Q4); Spearman of local score vs public win rate (recon §5, Q10) — [F-50](F-50.md) ratings/outcome models.
- Replay-drive agreement: share of recorded commands reproduced when a known-source bot is re-driven through a replay — [F-51](F-51.md).
- Three-number form: not applicable.
