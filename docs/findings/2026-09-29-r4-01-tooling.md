Confirmed already-correct for `bot.toml language = "c++"` directories: arena/bench/golden launch
bots through the same `_resolve` → `Project.compile()` path as `unswbc run` (stamped build keyed on
**all** include-pattern sources, headers included → no stale native builds); the sandbox wasm cache
(hash covers only `.c/.cpp`) is purged per sandbox game by `arena.py`; sandbox points report with the
boot turn separated; `ablate.py` is pure post-processing. Fixed:

- **Loud compile failures.** `bench.py` printed "build failed" and then failed every fixture in
  flight; it now aborts with exit 2 before any game. `run_panel.py` prebuilds every bot **serially**
  in the parent process (also fixing the Ares V04 "transient permission error" parallel-startup race
  on `.unswbc-build`) and exits 2 on any build error.
- **meter.py `--mode cxx`.** The parse/sense/policy/BFS breakdown for any C++ bot whose sources
  implement the `CX_METER` protocol: built with `#define CX_METER 1` prepended to main.cpp, the bot
  prints `CX_METER parse=<us> sense=<us> policy=<us> bfs=<us>` to stderr once per turn;
  `arena.run_game(meter_prefix="CX_METER")` drains stderr per turn and returns the lines (stderr
  never reaches the engine or the replay). `--mode auto` picks cxx iff the sources mention CX_METER
  (Ares sources mention neither → anna/ANNA_MEASURE stays the default there; the Ares bots carry no
  instrumentation and R-4 may not edit them). Verified end-to-end under the sandbox with the
  committed fixture bot `tools/cx/tests/fixtures/cxmeter-bot` (phase lines collected, points/boot
  intact, 0 errors).
- **golden `suite`.** `golden.py suite BOT [--transcripts DIR]` replays one bot against every
  transcript under a directory — the V04 behaviour-parity run as a command. Ares V06 (C++) against
  the Python-recorded reference transcripts compiles, replays, and reports divergences with exit 1;
  yuna-v03-core against its own recording: 5,771 turns, 0 divergent, exit 0.

## Part 4 — the generalisation panel (b4b1c3b7c)

`run_panel.GEN_MAPS` = all 20 `maps/new/*.map` + the 9 `maps/var/*_tr.map` (29 maps; `maps/pub`
reconstructions stay out — C1-B showed their edges match live maps). `--panel gen` plays the same
ZOO round robin (1,624 games); `--bot bots/<x>` plays the candidate grid — 8 ZOO opponents × maps ×
both seats (160 on z1 per seed — the V06 protocol; 464 on gen). Output lives under
`build/zoo/<panel>-<bot>-<fp8>/`, keyed by the **runtime-source fingerprint**: SHA-256 over the
sorted source names and contents (bot.toml + every c/c++/python source, name and bytes
NUL-separated) — the convention the Ares findings quote, now written down in code; any source edit
moves the directory, so a replay set is reused only while the sources are untouched. z1 game ids are
byte-identical to the old generator, so existing z1 replays still reuse.

`benchmarks.py` degrades gracefully on maps with no field reference (BENCHMARKS §guardrails):
`derive`/`apply_field_rel` produce NaN `|map`/`|top`/`|pct` for unknown maps — never a division by a
missing median — and a metric with no saved reference is skipped rather than raising KeyError; the
scorecard reports those maps raw against the parent instead. Tests in `test_features.py`.

## Part 3 — the single-bot scorecard

    python -m tools.analysis.features.scorecard bots/<candidate> [--parent bots/<parent>]
        [--panel z1|gen|both] [--seed 1,2] [--jobs N] [--atlas off] [--sandbox] [--replay-only]

Runs (or reuses, fingerprint-keyed) the panel, extracts features, scores against the fixed
references in `docs/analysis/benchmarks/`, and prints the two Ares-V06 tables (tier-1 with parent
deltas, tier-2 with % change), the panel W–L–D and expected-score share, the generalisation block
(raw-vs-parent, `|map` marked unavailable — no reference exists there), the CPU probe block when
`--sandbox` ran the 4 probe fixtures, and one line:

    GATE: pass|hold|fail — <reason>

applying BENCHMARKS §"How to use it" step 4 literally: **fail** = economy mean down OR any tier-2
rate up >10 % (including from zero) OR panel win rate down; **pass** = economy mean +≥0.05 of field
median with dragons and length at r100 not falling (and no fail trigger); **hold** = everything
else — hygiene holding or up with the economy short of the bar. It writes
`game_stats/runs/<candidate>-<panel>-s<seed>.json` (full stats + gate) and a paste-ready `.md`
block. `--atlas off` plays a `build/cx/atlas-off/` copy with `ATLAS_ENABLED = false` (exactly one
flip expected; the measured snapshot is never edited), carrying its own fingerprint.
`--replay-only` refuses to run games and fails if any replay is missing.

Also fixed on the way: `python -m tools.analysis.features extract` crashed under spawn-based
process pools (macOS) because its worker lived in `__main__`; the worker is now
`extract.extract_one` and the CLI is platform-neutral.
