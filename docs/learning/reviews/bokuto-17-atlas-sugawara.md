## What the code does (read from ../wt-bokuto/bots, file bridge, read-only)

- `atlas.hpp` is generated by `tools/bokuto/build_atlas.py` from `maps/live/*.map`. Each entry holds a map's name,
  full edge grid (kelp/portal/open), portal pairs and pearl-bed classes.
- `bokuto-13-cull` (trial 2, live as 17530; same mechanism in carthage-05): `n_maps = 10`.
- `bokuto-17-atlas` (announced in Bokuto's 08:17Z line as the next version): `n_maps = 17` (adds australia,
  islands, unsw, maze, stripes, tower_defense, ...). `world.hpp::atlas_match` picks one map once >= 60 edges are known,
  then overwrites unknown edges and seeds `atlas_bed`; `bokuto_branch.hpp:121-122` counts never-observed atlas beds.
- The 08:17Z line's claimed gain ("first Weakhold games against asahi-05 flip to wins") arrives with the 17-map atlas
  and whole-map routing to far targets: routes through terrain the dragon has not seen.

## Verdict: flag before any pool, screen or ladder slot

- This is map identity in the strict sense of D-033 and D-069 §C (P-3, rejected for a 60x40 gate): the bot decides
  which live map it is on and loads that map's unseen terrain and beds. `_common.md` hard rule: "No map identity in
  any bot: structure only." The 10-map atlas was inherited from the scaffold and tolerated (decisions l.474: "whether
  its policy consumes it must be measured"; D-078 §E treats it as a lead). Extending it to all 17 maps and feeding it
  into routing is a new, larger use, not the inherited one.
- Why it matters now (D-079 §D): every local harness plays only the 17 template maps, which a 17-map atlas knows
  exactly; the ladder also draws hidden layouts (Kageyama: 5 variants, about 11 % of ranked games) whose terrain
  matches a template but whose beds differ. An atlas gain is therefore one the local pool overstates by construction.
  Caveat: on Asahi's variant block 13-cull's 10-map atlas did not hurt (72/80 vs c05 63/80), so this is not offered as
  the explanation of trial 2's interim.
