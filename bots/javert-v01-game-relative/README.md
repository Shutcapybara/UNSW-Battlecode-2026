# Javert v01: game-relative density policy

Promoted release: an exact executable copy of `javert-x03-policy` (LEN_DENSITY
+ POLICY3 enabled, FRONTIER_MODE = 0, tracing disabled), selected by the
pre-declared rule after the frozen screen and promoted by the fresh-reserve
criterion: **10–2** versus the density-control fork's 7–5 and Monte Christo
v01's 5–7 on two new frozen map families (portal web + gated honeycomb)
against Sinbad v03 / Hunter v20 / Drake v11, both sides, zero errors.

What it adds over Aramis v02 (mode 0): visible ally/enemy **length** density
in a second reserved sonar ray (type-7 packets, position-guarded merge), a
decayed length field, and a policy that demotes REPRODUCE in confined pockets
(openness feature) and boosts early population-saturated ATTACK approaches.
Reserve attribution: the information layer (also present in x02, 10–2)
produced the entire gain — three honeycomb losses became wins (final longest
dragon 4→34, 10→17, 8→16); the policy layer was outcome-neutral there.

Judge coverage: six sandbox games vs Hunter v20 (Arena/Stronghold/Big Empty,
both sides): 65k metered turns, zero caught errors/timeouts, maximum
96,956,430 CPU points (3.04M under the 100M limit, inherited worst-case turn),
22,544,384 bytes. Native screens remain the development evidence.

See [the Javert report](../../docs/javert.md) for the controlled study and
`tools/javert/` for frozen sources, rules and run records. Monte Christo v01
stays available as the previous playing baseline.
